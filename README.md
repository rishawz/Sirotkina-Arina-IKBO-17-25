# Инструмент визуализации графа зависимостей (NuGet)

Практическая работа № 2, дисциплина «Конфигурационное управление»,
вариант 25. Статус: этап 4 из 5 (дополнительные операции).

## 1. Общее описание

CLI-приложение на Python 3 (только стандартная библиотека). Источник
параметров - опции командной строки. Приложение строит граф зависимостей
пакета NuGet с учётом транзитивности (рекурсивный DFS), ограничивает
глубину анализа, пропускает пакеты по подстроке в имени, корректно
обрабатывает циклы и умеет работать с тестовым репозиторием из файла.
На этапе 4 добавлен режим вывода обратных зависимостей (пакетов, которые
зависят от заданного); обычный результат выводится списком рёбер
`родитель -> зависимость`.

## 2. Функции и настройки

| Опция | Описание |
|-------|----------|
| `-p`, `--package` | имя анализируемого пакета (обязательна) |
| `-r`, `--repo` | URL репозитория NuGet или путь к файлу тестового репозитория |
| `-t`, `--test-mode` | режим работы с тестовым репозиторием |
| `-V`, `--version` | версия пакета (обязательна вне тестового режима) |
| `-a`, `--ascii-tree` | вывод зависимостей в виде ASCII-дерева |
| `-d`, `--max-depth` | максимальная глубина анализа, по умолчанию 3 |
| `-R`, `--reverse` | вывести обратные зависимости пакета (только с `--test-mode`) |
| `-f`, `--substring` | не учитывать пакеты, в имени которых есть подстрока |

Если `--repo` не задан вне тестового режима, используется
`https://api.nuget.org/v3-flatcontainer/`.

Обработка ошибок: некорректное имя пакета, версия, URL, отсутствующий
файл тестового репозитория, отрицательная или нецелая глубина - сообщение
об ошибке в stderr и код возврата 2.

Получение данных (модуль `nuget.py`): по протоколу NuGet v3
(Package Content, «flat container») запрашивается
`{repo}/{id}/{version}/{id}.nuspec` (id и версия в нижнем регистре).
Используются только `urllib` и `xml.etree` из стандартной библиотеки.
Зависимости всех групп `targetFramework` объединяются, повторы по имени
отбрасываются (остаётся первое вхождение).

Версии транзитивных пакетов (`versions.py`, `nuget_source.py`): берётся
нижняя граница диапазона из nuspec (NuGet выбирает минимальную
подходящую версию); если границы нет - последняя стабильная версия из
`{repo}/{id}/index.json`. Пакет раскрывается с версией из диапазона,
с которым он встретился первым.

Граф (`graph.py`): рекурсивный DFS. Узлы на глубине `--max-depth` не
раскрываются (глубина корня - 0). Пакеты, в имени которых есть
подстрока `--substring` (без учёта регистра), в анализе не участвуют;
корневой пакет не фильтруется. Циклы: узел повторно раскрывается, только
если до него найден более короткий путь, поэтому обход всегда
завершается; ребро, замыкающее цикл, остаётся в графе.

Тестовый режим (`testrepo.py`): `--test-mode --repo файл`. Формат файла -
строка `A: B C` (A зависит от B и C), `D:` - пакет без зависимостей,
имена - заглавные латинские буквы, `#` - комментарий. Версия не нужна.

Обратные зависимости (`reverse.py`, этап 4): строится инвертированный
индекс тестового репозитория, после чего используется тот же рекурсивный
DFS `build_graph`, но соседями узла служат пакеты, которые от него
зависят. Учитываются `--max-depth`, `--substring` и циклы. Запись
`B <- A` читается так: A зависит от B. Режим доступен только вместе с
`--test-mode`: протокол NuGet v3 не отдаёт индекс «кто зависит от
пакета», поэтому для реального репозитория обратные зависимости
получить нельзя - опция выдаст ошибку.

## 3. Сборка и тесты

Сборка не требуется. Запуск: `./run.sh <опции>` или
`make run ARGS="<опции>"`. Тесты: `make test`.

## 4. Примеры использования

Реальный репозиторий (нужен доступ в интернет):

```
./run.sh -p Newtonsoft.Json -V 13.0.3 -d 2
```

Тестовые репозитории лежат в `examples/`.

Цепочка и ветвление (`examples/chain.txt`):

```
$ ./run.sh -p A -t -r examples/chain.txt
A -> B
A -> C
B -> D
C -> E
(код возврата: 0)
```

Ограничение глубины:

```
$ ./run.sh -p A -t -r examples/chain.txt -d 1
A -> B
A -> C
(код возврата: 0)
```

Цикл (`examples/cycle.txt`), включая самозависимость:

```
$ ./run.sh -p A -t -r examples/cycle.txt -d 10
A -> B
B -> C
C -> A
C -> D
D -> D
(код возврата: 0)
```

Ромб с общей зависимостью (`examples/diamond.txt`) и фильтр по подстроке:

```
$ ./run.sh -p A -t -r examples/diamond.txt -d 10
A -> B
A -> C
B -> D
D -> E
E -> F
C -> D
C -> X
X -> E
(код возврата: 0)
```

```
$ ./run.sh -p A -t -r examples/diamond.txt -d 10 -f D
A -> B
A -> C
C -> X
X -> E
E -> F
(код возврата: 0)
```

Другой корневой пакет и глубина 0:

```
$ ./run.sh -p C -t -r examples/diamond.txt
C -> D
C -> X
D -> E
E -> F
X -> E
(код возврата: 0)
```

```
$ ./run.sh -p A -t -r examples/diamond.txt -d 0
Зависимости не найдены
(код возврата: 0)
```

Локальный NuGet-репозиторий (`python3 -m http.server -d examples/mock-nuget 8765`):

```
$ ./run.sh -p Demo.App -V 1.0.0 -r http://127.0.0.1:8765/ -d 5
Demo.App -> Demo.Core
Demo.App -> Demo.Logging
Demo.App -> Demo.Compat
Demo.Core -> Demo.Utils
Demo.Core -> Demo.Logging
Demo.Logging -> Demo.Utils
Demo.Compat -> Demo.Core
(код возврата: 0)
```

```
$ ./run.sh -p Demo.App -V 1.0.0 -r http://127.0.0.1:8765/ -d 5 -f Logging
Demo.App -> Demo.Core
Demo.App -> Demo.Compat
Demo.Core -> Demo.Utils
Demo.Compat -> Demo.Core
(код возврата: 0)
```

Ошибки:

```
$ ./run.sh -p Z -t -r examples/chain.txt
Ошибка: пакет Z не найден в examples/chain.txt
(код возврата: 2)
```

```
$ ./run.sh -p A -t -r README.md
Ошибка: строка 3: нет разделителя ':'
(код возврата: 2)
```

Фильтр, исключающий все зависимости корня:

```
$ ./run.sh -p Demo.App -V 1.0.0 -r http://127.0.0.1:8765/ -d 1 -f Demo
Зависимости не найдены
(код возврата: 0)
```

### Обратные зависимости (этап 4)

Кто зависит от `E` в ромбе (`examples/diamond.txt`), глубина 1 и полная:

```
$ ./run.sh -p E -t -r examples/diamond.txt -R -d 1
Обратные зависимости пакета E:
E <- D
E <- X
(код возврата: 0)
```

```
$ ./run.sh -p E -t -r examples/diamond.txt -R -d 10
Обратные зависимости пакета E:
E <- D
E <- X
D <- B
D <- C
B <- A
C <- A
X <- C
(код возврата: 0)
```

Фильтр по подстроке (пакеты с `X` не учитываются):

```
$ ./run.sh -p E -t -r examples/diamond.txt -R -d 10 -f X
Обратные зависимости пакета E:
E <- D
D <- B
D <- C
B <- A
C <- A
(код возврата: 0)
```

Цикл (`examples/cycle.txt`) и самозависимость:

```
$ ./run.sh -p D -t -r examples/cycle.txt -R -d 10
Обратные зависимости пакета D:
D <- C
D <- D
C <- B
B <- A
A <- C
(код возврата: 0)
```

Пакет, от которого никто не зависит:

```
$ ./run.sh -p A -t -r examples/diamond.txt -R
Обратные зависимости пакета A:
Обратных зависимостей нет
(код возврата: 0)
```

Ошибка: реальный репозиторий не поддерживает обратные зависимости:

```
$ ./run.sh -p Demo.App -V 1.0.0 -R
Ошибка: обратные зависимости доступны только в тестовом режиме: NuGet не отдаёт индекс «кто зависит от пакета», добавьте --test-mode
(код возврата: 2)
```
