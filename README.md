# Инструмент визуализации графа зависимостей (NuGet)

Практическая работа № 2, дисциплина «Конфигурационное управление»,
вариант 25. Статус: этап 2 из 5 (сбор данных).

## 1. Общее описание

CLI-приложение на Python 3 (только стандартная библиотека). Источник
параметров - опции командной строки. На этапе 1 приложение проверяет
параметры, загружает из репозитория NuGet описание пакета заданной версии
(`.nuspec`) и выводит его прямые зависимости.

## 2. Функции и настройки

| Опция | Описание |
|-------|----------|
| `-p`, `--package` | имя анализируемого пакета (обязательна) |
| `-r`, `--repo` | URL репозитория NuGet или путь к файлу тестового репозитория |
| `-t`, `--test-mode` | режим работы с тестовым репозиторием |
| `-V`, `--version` | версия пакета (обязательна вне тестового режима) |
| `-a`, `--ascii-tree` | вывод зависимостей в виде ASCII-дерева |
| `-d`, `--max-depth` | максимальная глубина анализа, по умолчанию 3 |
| `-f`, `--substring` | не учитывать пакеты, в имени которых есть подстрока |

Если `--repo` не задан вне тестового режима, используется
`https://api.nuget.org/v3-flatcontainer/`.

Обработка ошибок: некорректное имя пакета, версия, URL, отсутствующий
файл тестового репозитория, отрицательная или нецелая глубина - сообщение
об ошибке в stderr и код возврата 2.

Получение данных (модуль `nuget.py`): по протоколу NuGet v3
(Package Content, «flat container») запрашивается
`{repo}/{id}/{version}/{id}.nuspec` (id и версия в нижнем регистре).
Используются только `urllib` и `xml.etree` из стандартной библиотеки.
Зависимости всех групп `targetFramework` объединяются, повторы по имени
отбрасываются (остаётся первое вхождение). Тестовый режим (`--test-mode`)
пока не поддерживается - он появится на этапе 3.

## 3. Сборка и тесты

Сборка не требуется. Запуск: `./run.sh <опции>` или
`make run ARGS="<опции>"`. Тесты: `make test`.

## 4. Примеры использования

Реальный репозиторий (нужен доступ в интернет):

```
./run.sh -p Newtonsoft.Json -V 13.0.3
```

Локальная демонстрация без интернета: каталог `examples/mock-nuget`
содержит вымышленные пакеты `Demo.*` в раскладке «flat container».

```
$ python3 -m http.server -d examples/mock-nuget 8765
```

```
$ ./run.sh -p Demo.App -V 1.0.0 -r http://127.0.0.1:8765/
Прямые зависимости Demo.App 1.0.0:
  Demo.Core [1.2.0, )
  Demo.Logging 2.0.0
  Demo.Compat 1.0.0
(код возврата: 0)
```

```
$ ./run.sh -p Demo.Utils -V 1.0.0 -r http://127.0.0.1:8765/
Прямые зависимости Demo.Utils 1.0.0:
  (нет)
(код возврата: 0)
```

Ошибки:

```
$ ./run.sh -p Demo.App -V 9.9.9 -r http://127.0.0.1:8765/
Ошибка: пакет или версия не найдены: http://127.0.0.1:8765/demo.app/9.9.9/demo.app.nuspec
(код возврата: 2)
```

```
$ ./run.sh -p Demo.App -V 1.0.0 -r http://127.0.0.1:1/
Ошибка: не удалось загрузить http://127.0.0.1:1/demo.app/1.0.0/demo.app.nuspec: <urlopen error [Errno 111] Connection refused>
(код возврата: 2)
```
